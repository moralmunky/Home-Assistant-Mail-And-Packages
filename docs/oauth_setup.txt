SIGNING IN WITH GOOGLE OR MICROSOFT
Mail and Packages setup notes

Mail and Packages can read a Gmail or Microsoft 365 / Outlook mailbox by
signing in with the account itself instead of a password. That avoids app
passwords, which Google cancels every time the account password changes and
which many Microsoft 365 organizations turn off.

As with most Home Assistant integrations that use Google or Microsoft sign in,
you register your own OAuth app and give Home Assistant its client ID and
secret. Your sign in tokens stay on your own Home Assistant.


BEFORE YOU START

Every OAuth app needs this redirect URI, typed exactly like this:

    https://my.home-assistant.io/redirect/oauth

The first time you sign in, the my.home-assistant.io page asks for the address
of your Home Assistant (for example http://homeassistant.local:8123). That
browser remembers it after that.

One app for each provider covers any number of mailboxes.


GOOGLE (GMAIL)

1. Open the Google Cloud console (https://console.cloud.google.com/) and
   create a project. The name does not matter.

2. Open Google Auth Platform.

   Branding: enter an app name and a support email. Leave the logo empty,
   because adding one sends the app into Google's verification review.

   Audience: choose External, then click Publish app so the status reads
   In production. An app left in Testing hands out tokens that expire after
   7 days, and the mailbox would stop updating every week. An unverified app
   in production works for up to 100 accounts and shows a warning screen when
   you sign in (covered below).

   Data access: add the scope https://mail.google.com/

   Clients: click Create client, pick Web application, and add the redirect
   URI from above under Authorized redirect URIs.

3. Copy the Client ID and the Client secret.

4. In Home Assistant go to Settings, Devices & services, open the three dot
   menu, and choose Application credentials, Add application credential.
   Pick Mail and Packages, give it a name such as Google, and paste in the
   client ID and secret.

Personal Gmail accounts always allow IMAP. On Google Workspace accounts an
administrator can block IMAP or outside apps; if sign in works but the mailbox
is refused, ask them to allow it.


MICROSOFT 365 / OUTLOOK

1. Open the Microsoft Entra admin center (https://entra.microsoft.com/) and go
   to App registrations, New registration.

2. Name it whatever you like.

3. Supported account types: choose "Accounts in any organizational directory
   (Multitenant)". For outlook.com or hotmail.com mailboxes choose the option
   that also includes personal Microsoft accounts. Mail and Packages signs in
   through Microsoft's shared "common" address, which turns away apps set to a
   single tenant.

4. Redirect URI: platform Web, with the address from Before you start.

5. Open API permissions, Add a permission, and add both of these as delegated
   permissions:

     Office 365 Exchange Online (under APIs my organization uses):
     IMAP.AccessAsUser.All

     Microsoft Graph: offline_access

   If your organization requires it, an administrator clicks Grant admin
   consent.

6. Open Certificates & secrets, New client secret, and copy the secret's
   Value right away, since Microsoft only shows it once. The Secret ID next to
   it is not the secret.

7. Copy the Application (client) ID from the app's Overview page.

8. Add both to Home Assistant under Application credentials, the same way as
   step 4 for Google, with a name such as Microsoft.

IMAP has to be turned on for the mailbox. In the Exchange admin center
(https://admin.exchange.microsoft.com/) open Recipients, Mailboxes, select the
mailbox, choose Manage email apps settings, and turn on IMAP.

Client secrets expire (Microsoft allows up to 24 months). Make a new one before
the old one runs out and update the application credential in Home Assistant.


ADDING THE MAILBOX IN HOME ASSISTANT

1. Settings, Devices & services, Add integration, Mail and Packages.

2. Pick the Google (Gmail) or Microsoft (Outlook/Exchange) sign in option and
   enter the mailbox address as the username. It has to be the account you are
   about to sign in with; the sign in page selects it for you. Server, port
   and security are filled in already.

3. If you added more than one application credential, pick the one for this
   provider. Sign in and allow access. With an unverified Google app, click
   Advanced and then "Go to home-assistant.io (unsafe)" on the warning screen.
   Google shows the redirect site there, not your app name.

4. On my.home-assistant.io, click Link account.

5. Mail and Packages checks that the mail server accepts the sign in, then
   moves on to the usual sensor options.


TROUBLESHOOTING

Microsoft says AADSTS50194, "is not configured as a multi-tenant application"
    The app is set to a single tenant. Change Supported account types to
    multitenant (Microsoft step 3).

Microsoft says AADSTS50011, the redirect URI does not match
    Add the redirect URI as a Web platform URI, exactly as shown above.

Microsoft says Need admin approval
    Your organization wants an administrator to grant consent for the app's
    permissions (Microsoft step 5).

Microsoft says AADSTS7000215, invalid client secret
    The Secret ID was used instead of the secret's Value, or the secret
    expired. Create a new secret.

Google says Error 400: redirect_uri_mismatch
    Add the redirect URI to the OAuth client's Authorized redirect URIs.

Google says Error 403: access_denied
    The app is still in Testing and the account is not a test user. Publish
    the app (Google step 2).

A Google mailbox stops updating every 7 days
    The app is still in Testing. Publish it, then sign the mailbox in again.

"You signed in, but ... refused mail (IMAP) access"
    The address you typed is not the account you signed in with, IMAP is off
    for the mailbox, or the app is missing the mail permission.

"No OAuth app is set up for Mail and Packages yet"
    Add the client ID and secret under Application credentials first.

my.home-assistant.io asks for an address
    Enter your Home Assistant address once; the browser remembers it.
